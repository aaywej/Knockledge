## 1. Product Purpose & Core Mechanism

Knockledge is a native Android application for retroactive audio recording. Standard voice recording applications require users to start recording before speech begins. Knockledge continuously records audio into a rolling circular buffer in local storage.

When speech of interest occurs, the user knocks twice on the desk or phone body. The device accelerometer detects this gesture and saves the recent audio buffer (up to 5 minutes) as a permanent note. The application preserves the original audio recording for authentic playback. The system pre-processes audio (silence removal and normalization) for cloud or on-device AI transcription, note summarization, and timestamped chapter generation.

## 2. Platform Guarantees & Constraints

- **Platform Target**: Native Android (Jetpack Compose).
- **Touch Target Accessibility**: Every interactive control must measure at least 48 × 48 dp.
- **System Insets**: Layouts must support edge-to-edge display with status bars and navigation bars.
- **Predictive Back Navigation**: Screen transitions must support system Back gestures.
- **Visual Design Scope**: Visual styling, brand theme, color palettes, and component shapes remain open for design definition.

## 3. Screen Information Architecture & State Requirements

### Screen 1: Ambient Recording & Buffer Monitoring

**Functional Purpose**: Displays the live circular audio cache status and sensor detection state.

**Required Data & Actions**:
- **Cache Duration Display**: Current buffered audio length versus maximum configured limit (for example: 3m 42s stored out of 5m max).
- **Cache Activity Indicator**: Visual feedback showing that continuous background audio caching is active.
- **Gesture Detection Status**: Status indicating whether double-knock gesture detection is active.
- **Manual Capture Action**: Manual trigger button that saves the rolling buffer immediately as a fallback for the physical gesture.
- **Buffer Length Control**: Control to adjust buffer duration between 1 minute and 5 minutes.
- **Recent Captures List**: List of recently saved audio notes displaying capture timestamp, duration, processing state, and quick play action.
- **Navigation Actions**: Direct access to Settings and User Profile.

---

### Screen 2: Note Detail & Audio Playback

**Functional Purpose**: Plays back the original unmodified audio recording and supports topic navigation.

**Required Data & Actions**:
- **Audio Scrubber**: Timeline seekbar showing current elapsed time, total duration, and playback progress.
- **Chapter Markers on Timeline**: Visual tick indicators along the timeline marking start positions of each topic chapter.
- **Playback Controls**: Play, pause, seek forward, and seek backward actions.
- **Interactive Chapter List**: List of timestamped chapters generated by AI. Each item displays chapter title, start timestamp, and topic summary.
- **Active Chapter Indication**: Dynamic visual state indicating which chapter matches the current audio playback position.
- **Direct Chapter Seeking**: Selecting any chapter item immediately updates playback to that chapter timestamp.
- **Note Management Actions**: Rename note, export audio file, and delete note.

---

### Screen 3: AI Processing States & Note Summary

**Functional Purpose**: Triggers speech transcription and displays structured summaries and notes.

**Required States & Content**:
1. **Unprocessed State (Default)**:
   - Appears immediately after saving an audio buffer.
   - Informs the user that raw audio is saved and AI processing is available.
   - Provides an action button to start AI processing.
2. **Processing State**:
   - Displays progress across pipeline stages: audio pre-processing, speech transcription, and summary generation.
   - Provides error feedback with retry action if network or inference fails.
3. **Completed Summary State**:
   - **Executive Title**: Generated title under 10 words.
   - **Executive Overview**: High-level summary paragraph.
   - **Key Discussion Points**: Bulleted list of primary decisions, questions, or topics.
   - **Timestamped Transcript**: Segmented text transcript with speaker separation and timestamps.
   - **Processing Source Indicator**: Label indicating whether processing ran via Cloud AI or Offline On-Device models.
   - **Refresh Action**: Allows users who processed notes offline to request full cloud enhancement when connected.

---

### Screen 4: Application Settings

**Functional Purpose**: Configures buffer parameters, AI execution mode, and gesture sensitivity.

**Required Controls**:
- **Audio Buffer Window**: Control to set rolling cache duration from 1 minute to 5 minutes (default: 5 minutes).
- **Storage Consumption Display**: Current disk space occupied by cached audio.
- **Automatic AI Processing Toggle**: Switch to toggle automatic processing upon note capture. Default state is OFF (manual on demand) to conserve battery and data quotas.
- **Gesture Sensitivity Control**: Sensitivity adjustment for double-knock detection.
- **Gesture Test Area**: Interactive surface to test knock detection with instant visual or vibration feedback.
- **Authentication & Synchronization Status**: Active user account display and remote database sync toggle.

---

### Screen 5: Authentication

**Functional Purpose**: Secures user access before entering the application.

**Authentication Rules & Requirements**:
- **Mandatory Authentication**: Users must sign in before accessing recording features. Anonymous login and guest mode are prohibited to ensure private note partitioning.
- **Sign-In Options**:
  - Sign in with Google.
  - Sign in with Email and Password.
  - User registration flow collecting Display Name, Email, and Password.
  - Account collision error handling directing users to their original authentication provider.

---

## 4. Functional User Flows for UI Wireframing

1. **Ambient Recording to Note Capture**:
   - User opens the application -> Active cache displays running buffer.
   - User knocks twice on desk (or taps manual button) -> System confirms capture -> Note appears in recent captures list.
2. **On-Demand Processing**:
   - User opens unprocessed note -> Taps AI processing action -> System indicates progress -> Screen displays structured summary and transcript.
3. **Chapter Navigation**:
   - User listens to note -> Selects chapter from list -> Audio scrubber moves to chapter start time -> Audio continues playback.
